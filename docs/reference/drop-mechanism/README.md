# 投放机构（硬件子队交付）参考

> 来源：硬件子队交付，2026-09-23。飞控基线 Pixhawk 6C / ArduCopter 4.7.1。
> 性质：外部权威来源（硬件真机验证过的投放链路与参数）。我们决策/接口层的集成设计
> 与它的关系见 [ADR-0007](../../spec/adr/0007-drop-servo-vs-relay.md)。

本目录归档硬件子队的三份台架/遥控脚本，作为**验证过的参考**（命令时序、PWM 值、飞控参数）。
它们是**独立台架工具**，不是我们系统的一部分；我们的自主投放集成在 `cuadc_interface`/
`cuadc_decision`（见 ADR-0007），复用同一条飞控/舵机物理链路。

## 验证过的链路与关键事实

- **架构 B（我们集成所依据的）**：地面/机载 → MAVLink（数传/USB）→ Pixhawk → **SERVO9(=AUX1)**
  PWM → 投放舵机。指令 `MAV_CMD_DO_SET_SERVO`，值是 **PWM 微秒**。
- **执行器是连续旋转舵机/齿轮电机**：**1500µs=停**、**1100µs=一个方向**、**1900µs=另一方向**。
  一次投放 = 发投放方向 PWM **持续一段时间（脚本用 1.9 / 1.975 / 3.330 s 不等）**，再**必须回
  1500µs 停住**。真正的投放动作时长按硬件实测设定。
- **飞控参数（交付时）**：`SERVO9_FUNCTION=0`（未分配 PWM 输出，允许 `DO_SET_SERVO` 驱动）、
  `SERVO9_MIN/TRIM/MAX=1000/1500/2000`、`SERVO9_REVERSED=0`、`SERVO_GPIO_MASK=0`。
  注意：`RC9`（遥控器输入通道 9）≠ `SERVO9`（飞控输出通道 9=AUX1），只是编号相同。
- **供电**：AUX 信号由飞控产生，但 AUX 的舵机电源轨不由 USB 供电——执行器须由独立稳压电源
  供电，信号与电源共地。树莓派 GPIO 只出 3.3V 逻辑，不能给执行器/舵机供电。

## 三份脚本

| 文件 | 路径/控制方式 | 用途 |
|---|---|---|
| `skydroid_calibrator_pi.py` | 树莓派 GPIO18 直接输出 PWM + GPIO23 读 HOME 微动开关 | 带回零开关的台架标定（架构 A，不经飞控）。当前主逻辑被注释，直接跑只打印提示并回中立退出 |
| `skydroid_laptop_test.py` | 电脑 → Pixhawk USB(COM12/115200) → MAVLink → SERVO9 | 交互式空载台架测试（t/p/x/q + 自定义 `<PWM> <秒>`） |
| `skydroid_laptop_test911.py` | 电脑 → Pixhawk(COM5/57600) → MAVLink → SERVO9 | 同上，带运行时长上限与计时反馈 |

三份都**依赖人工输入 / 手动运行**，是台架/遥控工具，**不能**作为正式比赛的自动投放方式——
比赛要求飞行器起飞后自动完成任务。自动投放由我们系统实现（ADR-0007）。

## 我们集成时对飞控配置的改动（见 ADR-0007）

为满足「除投放 state 外投放通道都归遥控器」的需求，我们把投放输出从 `SERVO9_FUNCTION=0`
（DO_SET_SERVO）改为 **`SERVO9_FUNCTION=RCIN9`（RC 直通）**：平时遥控器拨杆直控投放，仅决策
进 `DROP_PAYLOAD` 态时接口层发定时 `RC_CHANNELS_OVERRIDE` 短暂接管。**这需要硬件子队在飞控上
改该参数并复验 override 链路**，且要求飞手投放拨杆平时停在中立(1500µs)。

## 安全（沿用交付文档）

- 软件回中立(1500µs)不能替代物理臂展开关/急停。
- 首次测试排除桨、卸载水瓶、固定机身；分级推进：台架空载 → 挂载 → 整机 → 命令行打通 →
  地面测通 → 真机单点。
- ACK/序列完成 ≠ 载荷一定脱离（无称重/角度闭环，MAVLink 路径无 HOME 反馈）。
