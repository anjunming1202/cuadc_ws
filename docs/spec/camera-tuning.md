# 相机调参：快门/去模糊（item 3）

> 活文档：伴随机相机**拍摄参数**(快门/曝光、增益…)的台架调参方法与实现约定。
> 目标是给感知(CV)一组"在真实运动下足够清晰、且曝光/噪声可接受"的相机设置。
> 属伴随机侧相机职责，与飞控内部调参无关(见 `00-index` 非目标)。

## 1. 目标与范围

> **实测相机(Pi5,dmesg 确认)**：**IMX519**(16MP、**卷帘快门**)+ **AK7375**
> 自动对焦马达。故本调参**必须一并管对焦**(AF 乱找焦=模糊/逐帧不一致);卷帘
> 意味着快速运动会有倾斜/果冻,不只是条纹(见 §7)。曝光/增益范围是 IMX519 专属,
> 具体上下限以真机 `rpicam`/picamera2 查得为准。

- **目标**：定出**快门(曝光时间)** + **增益(ISO)** + **对焦(固定焦/关 AF)**
  (必要时含 sensor mode/分辨率),使比赛影像(投放区检测、侦察)在飞行的真实
  运动下运动模糊 ≤ 可接受阈值,同时曝光够、噪声可控、焦稳定。
- **范围内**：快门↔增益↔噪声↔模糊的权衡;节拍器受控实验;把结论回灌成相机
  服务(tee)的运行时配置。
- **暂不含**(触及即标注,不在本轮定死)：相机服务是否转多流/换 picamera2(见 §6)、
  去畸变(每消费者后处理)、CV 算法本身。

## 2. 物理：模糊 = 快门 × 像面速度

运动模糊的像素条纹长度约为

```
L_blur(px) ≈ v_px · T_shutter
```

`T_shutter` 越短模糊越小;但曝光变暗 → 要么升增益(噪声↑)、要么接受更暗。
所以是 **快门↔增益↔噪声↔模糊** 的权衡,没有免费的清晰。

`v_px` 是目标在**像面**上的速度,由飞行实际决定:

```
v_px ≈ f_px · (v_ground / h)      # 平飞掠过地面目标
     + f_px · ω                   # 机体角速度(抖动/转向)
```

`f_px`=焦距(像素)、`v_ground`=地速、`h`=相对目标高度、`ω`=角速度(rad/s)。
**调参不能只"看着清晰"**,要对着这个 `v_px` 定 `T_shutter`,使 `L_blur ≤ L_allow`
(`L_allow` 由 CV 能接受的模糊像素数给出)。

## 3. 节拍器测试（受控、可复现的运动标尺）

节拍器提供一段**已知、可重复**的往复运动当"模糊标尺":在摆臂上贴高对比标记,
相机固定(三脚架),只让节拍器动。

推荐做法(两选一,可都做):

- **严格法(可映射到飞行)**：调节拍器 BPM/摆幅 + 相机距离,使标记在摆动中心的
  **峰值像面速度 ≈ 飞行估计的 `v_px`**;再扫快门,找到条纹 `L_blur ≤ L_allow` 的快门。
- **实用法(快速)**：固定一个"接近飞行"的节拍器速度,扫快门,逐档看标记条纹长度 +
  画面亮度/噪声,挑"够清晰且不过暗/过噪"的一档。

同一档要连拍多帧(模糊随摆动相位变化,摆动中心最糊,取**最大条纹**为准)。

**最终校验(飞行侧,可选但更真)**：手持或试飞时读 `udpin:14551` 的角速度
(`ATTITUDE`/`RAW_IMU` 的 gyro),给每帧打上**实际 ω**,验证台架挑的快门在真实
抖动下确实达标——这正是"拍照同时读遥测"对**调参**的真实用处(给帧标注真运动)。

## 4. 要扫的参数与要测的指标

- **扫**：快门(如 1/30…1/2000 s,以 µs 给)× 几档增益。
- **每帧测**：
  - `L_blur`(px)：标记条纹长度——最直接的运动模糊量;
  - 全局锐度(Laplacian 方差)——次要参考;
  - 亮度均值 + 噪声估计——判断曝光是否够、增益是否过噪。
- **产出**：`L_blur / 亮度 / 噪声` vs 快门(各增益档)的表/图 → 选定工作点。

## 5. 实现

### 5.1 给 `CameraBackend` 加拍摄控制（cylinder_dataset 里的现有相机后端）

现状：`dataset_core.CameraBackend` 用 picamera2 / rpicam-still,**不能设曝光/对焦**。
item3 要加**手动曝光/增益 + 对焦**(并**关 AE 与 AF**,否则扫描被自动补偿/找焦污染):

- rpicam-still：`--shutter <us>`、`--gain <x>`、`--awb off`/`--awbgains`、关 AGC/AE;
  对焦(AK7375)`--autofocus-mode manual --lens-position <dpt>`(0=无穷远)。
- picamera2：`controls={"AeEnable": False, "ExposureTime": us, "AnalogueGain": g,
  "AfMode": Manual, "LensPosition": <dpt>}`。

### 5.2 单独的调参脚本（复用,不耦合）

- **单独脚本**(如 `tune_shutter.py`)：独占相机 → 扫 (快门, 增益) → 每档拍几帧 →
  算 `L_blur`/亮度/噪声 → 写盘 + 打印/画汇总。**复用** `dataset_core` 的
  `CameraBackend`(扩展后)/`DatasetWriter`/(可选)`udpin:14551` 位姿读取,不重造。
- **为何单独而非 dataset 加个模式**：dataset 目的是"固定设置批量采集",调参目的是
  "扫参数比效果",控制流与产出不同;塞一起是把两个关注点耦到一个脚本。
  两者共享的只是"取帧 + 元数据",走**复用底层**而非合并脚本。

## 6. 相机模式与结论回灌 runtime（含一处开放决策）

- **两种相机模式**(见 `onboard-runtime.md`)：串流(tee 持有、固定设置、多消费者读
  5602/5600) vs 控制/调参(脚本独占、设参数)。**调参在台架跑控制模式(先停 tee)**,
  产出的 (快门, 增益) 随后成为 tee 的**运行时配置**。停/起 tee 安全(相机无飞控串口
  那种交接卡死问题)。
- **开放决策**：当前 tee 是 gst `libcamerasrc ! x264enc`。要把选定曝光/增益**钉死**到
  运行时,需确认 `libcamerasrc` 能否 pin 这些控制;若不能/不便,可能把相机服务
  **转成 picamera2 产生端**(顺带更好支持"编码前多流、每消费者不同质量",见
  onboard-runtime 的相机多流开放问题)。**调参结论会驱动这个决策,本轮先不定死。**

## 7. 实际情况 / 坑（先想清再上手）

- **必须关自动曝光/AGC**扫描,否则相机自己补偿,曲线全乱。
- **光照恒定**：一次扫描期间别变光,否则亮度混淆快门效果。
- **相机固定**、只让节拍器动;标记高对比。
- **快门 ≤ 1/帧率**：大幅缩快门后帧率可保,但更短快门更需要光/增益。
- **卷帘快门**(IMX519 已确认是 rolling shutter)：快速运动会产生**倾斜/果冻**而不只是
  条纹,判读模糊时区分;缩快门能减轻但消不掉卷帘几何畸变。
- **对焦(AK7375)**：扫描/比赛都要**关 AF、固定 lens position**在目标工作距离,否则
  AF 找焦会让"清晰度"逐帧漂、把模糊测量搅乱;飞行中 AF 抽风也会毁帧。
- **台架 ≠ 飞行**：节拍器只标定"模糊-快门"关系,最终快门要对着飞行 `v_px`(或 §3
  的实测 ω)定,别只在台架"看着清楚"就收工。

## 8. 交付 / 验收

1. 扩展后的 `CameraBackend`(手动曝光/增益/对焦、关 AE 与 AF)。
2. `tune_shutter.py` + 一次台架扫描数据(`L_blur`/亮度/噪声 vs 快门×增益)。
3. 选定的比赛工作点 (快门, 增益, 固定对焦)(对着 `v_px` 或实测 ω 给出依据,
   不是"看着清晰")。
4. §6 开放决策的结论:tee 保持 gst 钉参数,还是转 picamera2(多流/可控)。
