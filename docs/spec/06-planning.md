# 06. 规划/决策——任务状态机

## 任务触发与准备

三个独立物理开关，职责不重叠：

- **总电源开关**：给伴随计算机 + 飞控通电，触发伴随计算机 systemd
  开机自启所有 ROS2 节点，飞控走 PreArm 检查。准备区阶段使用。
- **任务开始开关**：独立于总电源，团队在起降点、按完比赛计时器开关
  之后触发，是 `WAIT_TASK_START` 条件的信号源——直连伴随计算机 GPIO，
  软件直接读电平触发，不经过飞控、不经过接口层/MAVLink。触发后状态机
  自动执行到底，不再需要人工介入。
- **安全开关**（规则硬性要求）：仅用于紧急停止，直接硬件切断动力，不
  经过软件判断，即使伴随计算机死机也能生效，赛前需向裁判演示。

不合并总电源和任务开始开关：两者发生的时间和地点不一样（准备区通电 vs
起降点触发起飞），合并意味着要么在准备区通电瞬间就误触发起飞（违规、
危险），要么每次都要在起降点重新断电重上电触发（浪费比赛时限、增加
二次冷启动失败风险）。不合并任务开始开关和安全开关：语义相反（启动 vs
切断动力），且安全开关按规则应保持纯硬件、软件无关。

## 任务状态机（细化版）

```
INIT
  ↓ 系统自检完成
WAIT_VEHICLE_READY     — 心跳 + EKF/GPS 正常 + PreArm 通过（订阅接口层遥测判断）
  ↓
WAIT_TASK_START        — 等任务开始开关的 GPIO 信号
  ↓
ARM_AND_TAKEOFF        — 依次调 Arm、Takeoff service，确认爬升到目标高度
  ↓
NAVIGATE_TO_DROP_ZONE  — goto_location 飞到投放区扫描路径的第一个点（区域位置固定，筒的位置随机，需要边飞边找）
  ↓
SEARCH_DROP_TARGETS    — 按扫描路径飞行，订阅感知的检测结果攒帧收敛出候选筒的位置+视在尺寸，攒够候选就按策略选一个目标（重新进入这个状态两次，第二次沿用第一次没用完的扫描/候选进度，不清零）
  ↓
APPROACH_DROP_TARGET   — 闭环靠近选中的筒：先在巡航高度靠近到一定范围内（避免离目标太远就急着降高度、过早丢视野），再水平+高度一起收敛到最终容差，全程持续用最新一帧检测刷新目标估计，不是靠 SEARCH 阶段算出来的一个坐标飞到底
  ↓
DROP_PAYLOAD           — 触发投放，等确认反馈
  ↓ 已投放次数 < 2 → 回 SEARCH_DROP_TARGETS 选下一个目标；== 2 → 继续
NAVIGATE_TO_RECON_ZONE — goto_location 飞到侦察区
  ↓
SURVEY_RECON_ZONE      — 飞扫描路径覆盖侦察区，把检测到的每个筒带入摄像头视野给图传看清，按位置去重记录"已覆盖"列表，直到 5 个都覆盖或超时
  ↓
RTL_OR_LAND            — 切 RTL/LAND，等落在 H 点内、螺旋桨停止、disarm
```

> `working-notes.md` 里此前拍板过一版更粗的状态机：`INIT →
> WAIT_VEHICLE_READY → WAIT_TASK_START → ARM_AND_TAKEOFF →
> NAVIGATE_TO_DROP_ZONE → DETECT_AND_DROP → NAVIGATE_TO_SURVEY_ZONE →
> DETECT_AND_REPORT → RTL_OR_LAND`。上面是把 `DETECT_AND_DROP` /
> `DETECT_AND_REPORT` 两个粗状态展开后的版本，属于正常迭代，不是推翻
> （见 `00-index.md` 开头"活文档"的说明）。

## 投放/侦察两个任务的状态数量不对称，是有意的

投放需要"找候选 → 精细对准 → 执行不可逆动作"三种性质不同的行为（尤其
精细对准要求的精度跟一般搜索完全不是一回事），且要重复两次，所以拆成
三个状态；侦察全程是同一种"覆盖扫描"行为，没有精细对准、没有不可逆
动作这个环节，所以只有一个状态。这个状态数量的划分依据是"行为性质"，
不是"要不要飞扫描路径"——投放区（8m×5m）和侦察区一样，一个悬停点看不全
整个区域，`SEARCH_DROP_TARGETS`/`SURVEY_RECON_ZONE` 都需要飞扫描路径，
只是投放区找齐候选后还要接精细对准+投放两个额外阶段，侦察区扫完就结束。

## 投放目标怎么选，以及为什么选不出更聪明的策略

按视在尺寸挑目标（比如"优先选最小的，命中分最高"）这类具体策略是可插拔
的一层，独立于状态转移逻辑，实机测试后大概率要调整（哪个策略最后表现
最好、要不要换成别的）——策略本身是实现细节，见
[`cuadc_decision/README.md`](../../src/cuadc_decision/README.md)。

两次投放之间没有办法根据"上一次投得准不准"来动态调整下一次的目标：
命中投放区哪个区（A/B/无效）是投放物落地后的物理结果，机上没有任何
传感器能在飞行中实时判断（跟上一节"先投放后侦察的判定依据"是同一个
物理限制）。能用来影响第二次选择的只有"上一次投放动作本身有没有被
确认执行"（`set_relay` service 的返回值），不是命中效果。所以策略层面
能做的只有"排除已经投过的位置，从剩下的候选里选"，这是这个限制下的
能力上限，不是偷懒简化。

圆筒有高度（0.3m），非正上方观察会有视差——拍到的筒顶中心跟地面真实
中心之间有偏移，偏移量正比于观察角度/水平偏移量。这个问题不需要靠
感知层做显式几何修正：`APPROACH_DROP_TARGET` 的闭环持续用离目标更近、
因此更准的新测量替换旧估计，越靠近视差越小，反复迭代本身就会把这个
系统偏差磨掉。感知层要不要额外做视差修正，是感知模块自己的算法设计
问题，不在这份状态机文档的范围内。

## "先投放后侦察"的判定依据

赛规要求"先投放、后侦察"。`NAVIGATE_TO_RECON_ZONE` 的进入条件是**两次
`set_relay` 都拿到了确认反馈**，不是"确认命中有效区"——命中投放区哪个
区（A/B/无效）是投放物落地后的物理结果，机上没有传感器能实时判断，也
不需要判断，不影响这条状态转移的判定。

## 侦察区标识识别不在软件职责范围

`SURVEY_RECON_ZONE` 只负责让摄像头覆盖到每个筒、给图传看清，不做标识
分类——危险化学品标识由机组人工肉眼经图传识别，见
[ADR-0003](adr/0003-recon-identification-visual-downlink.md)。这也是
这个状态没有沿用 working notes 里原本 `DETECT_AND_REPORT` 这个名字的
原因："REPORT"这部分已经不是软件职责。

## 跨状态的强制打断（failsafe / 任务时间预算）

除了上面这条主线，还有一类"不管当前在哪个状态，满足某个条件就强制
跳转"的规则，两种性质不同但机制相同：

- **任务逻辑安全响应**：比如电量低于（团队自定的、比飞控硬 Failsafe
  更保守的）阈值时提前 RTL。飞控自己的硬 Failsafe（低电、失联、GPS
  异常）已经在飞控固件层处理，见 `00-index.md` 横向关注点；这里说的是
  决策层基于遥测做的任务级响应。
- **任务时间预算**：比如投放阶段耗时太久，为了保住侦察/降落这些相对
  稳拿的分，强制放弃继续投放、提前进入侦察区。

这两类触发原因不同，但都是"满足条件就强制转移、跳过当前状态本来该做
的事"这同一种机制。具体阈值、覆盖哪些状态、每个阶段怎么差异化处理，跟
`00-index.md` 横向关注点里"具体约定待后续展开"一致，本文档暂不展开，
等实现/实测阶段再细化。

## 硬件单点测试

投放区任务可以不从起飞区开始，单独拿去实机调试：决策节点支持从
`NAVIGATE_TO_DROP_ZONE`（或更早的某个状态）直接起步，也可以让投放完
两次直接切 RTL、不用飞去侦察区。这两个入口默认值下跟正常任务流程完全
一样，只有显式指定才会走这条路径，不影响正常比赛流程——具体怎么传参见
[`cuadc_decision/README.md`](../../src/cuadc_decision/README.md)。
