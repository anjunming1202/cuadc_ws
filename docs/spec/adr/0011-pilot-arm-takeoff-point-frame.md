# 0011. 解锁归飞手、飞手夺控即 Pi 停手、局部坐标以起飞点为原点

**Status**: Accepted

## Context

2026-10-04 首次真机飞行测试暴露四个问题：

1. **Pi 解锁让 RC 解锁开关和飞机状态不一致**。Pi 解锁后开关还停在 disarm 挡，飞手“拨到 disarm”没有反应，要先拨上去再拨下来才能停桨；飞手忘了拨上去，整次飞行都是这样。紧急情况下多一步。
2. **RC 模式开关会顶掉 Pi 设的模式**。GCS 设的模式保持到开关挡位**变化**为止；开关停在 ALT_HOLD 挡时 GUIDED 被拒。真机在 GUIDED 下直接解锁也被 PreArm 拒过。
3. **飞手夺控后 Pi 会抢回控制**。Pi 的步骤失败兜底切 RTL；电量/failsafe 守卫也会切 RTL。飞手拨开关接管后，Pi 等不到到位而超时，兜底再切 RTL，把控制权抢回来。
4. **飞控 `LOCAL_POSITION_NED` 原点不是起飞点**。真机 EKF 原点在开机时定，实测离起飞地面 z 偏 0.9–2.1m、xy 偏数米（sim 里则是固定的世界原点）。接口契约写的是“相对起飞点”，但实际没有做到。高度确认、航点、感知反投影（假设 z=0 是地面）都会偏。

## Decision

1. **解锁和上锁只归飞手 RC，Pi 不发 arm**。起飞条件是固定顺序：放行信号 → 放行之后看到一次“未解锁→解锁” → 解锁时模式是 STABILIZE → Pi 1s 内切 GUIDED 并起飞。最后一个动作永远是飞手解锁，Pi 反应快，赶在飞控 `DISARM_DELAY` 自动上锁之前起飞。
2. **飞手/飞控接手后 Pi 永久停手**。Pi 接管后（任务：起飞指令被接受；测试节点：GUIDED 确认），出现 Pi 不会设的模式或空中被上锁，就停止一切指令和模式切换，包括安全守卫的 RTL。只有 Pi 自己的步骤失败、且飞手没有介入时，才兜底切 RTL/LAND。
3. **局部坐标原点 = 最近一次解锁的位置，由接口层统一换算**。发布 `local_position` 时减去原点，收到 `position_target_local` 时加回原点。上锁后原点保持不变（落地后读数仍相对起飞点），下次解锁时重新设定；从未解锁过时跟随当前位置。任务的场地坐标加 `takeoff_point`（起飞点的场地坐标）字段，加载时换算。
4. **sim 没有飞手**：`emulate_pilot_arm` 只在 sim 打开（测试节点由 sim 包装脚本传参，任务由 `mission_logic.sim.yaml` 打开），在“等飞手解锁”这一步替飞手切 STABILIZE 并解锁；之后的判定和真机完全相同。

不采用的方案：
- 放行和解锁各自独立检测再取 AND：先解锁再放行时，起飞由看不到飞机的操作员触发；而且放行必须在 `DISARM_DELAY` 内发出。
- 各个使用方自己记起飞基线：每个新使用方都要记得处理，感知反投影也要单独改。
- Pi 解锁、飞手事后补拨开关：就是问题 1。

## Consequences

- 接口层的 arm 服务保留，但飞行测试和任务都不再调用（只有 sim 模拟解锁、arm 检查的兜底上锁会用）。
- 任务状态 `ARM_AND_TAKEOFF` 改为 `WAIT_PILOT_ARM` + `TAKEOFF`，新增终态 `PILOT_TAKEOVER`。所有场景都必须经过放行和等解锁：`drop_zone_bench` 的 `initial_state` 改为 `INIT`（之前是直接从起飞开始，真机单点测试会一启动就起飞）。
- 现场前提：模式开关在 STABILIZE 挡解锁、Pi 飞行期间不动开关。RTL 落地后飞控停在 RTL 模式，下一次飞行前要拨一下开关回到 STABILIZE。
- 原点是解锁时的**飞控**位置，地面在它下方 `fc_rest_clearance_m`（实测 0.31m）。决策接近算法本来就按这个定义算相机离地高；感知反投影原先假设 z=0 是地面（sim 原点恰是世界地面才成立），改为筒顶平面在 `down = fc_rest_clearance_m − 筒高`（`camera.<profile>.yaml`）。漏掉这一项时 sim 斜视定位偏 +0.11m（反投影量测：+0.14 vs 基线 +0.03），补上后与基线一致。
- 桩感知（`stub_perception_node`）自己按世界坐标造检测，仍假设出生点在世界原点，只适用于正常仿真世界。
