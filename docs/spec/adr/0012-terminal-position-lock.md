# 0012. 末端对准改为锁定目标位置，由飞控位置环对准（短窗 PBVS）

**Status**: Proposed（sim 对比 + 实飞验证后再定是否成为默认）

## Context

2026-10-05 实飞单点（录制 `20261005_145245_single_drop`）：末端在 1.2–1.6m 水平来回摆
±10–15cm、周期 2.5–4.7s，迟迟进不了锥面、降不到投放高度。录制里**速度指令→实际速度滞后
0.56–0.92s**（图像链路只有 ~0.07s）。[ADR-0005](0005-terminal-align-visual-servoing.md) 的末端
IBVS 是"像素偏差 × kp → 速度指令"的外环，外环里串着飞控这 ~0.7s 的速度响应，kp 1.2 下相位
裕度只剩十几度 → 极限环。图像延迟补偿解决不了这一项。

ADR-0005 否掉 PBVS 的理由是世界坐标定位误差 0.5–2.5m。那是**整段用一个世界坐标**（SEARCH
斜视聚类、高度/挂载误差、GPS 漂移）。末端情况不同：

- 低空近 nadir，反投影对高度/姿态误差不敏感；拍照时刻位姿已对齐（3f8bee7，配对 100%）；
- 只用**最近 ~1s** 的检测估目标位置：GPS/EKF 慢漂移同时作用在飞机位置和目标估计上（同一
  EKF 坐标系），相对误差只剩窗口内的漂移量，cm 级；
- 目标是静止筒，估计不依赖当前运动，外环里不再有飞控响应。

## Decision

新增接近模块 `position_lock_descent`，与 `cone_descent_ibvs` 并列、启动参数切换：

1. **粗段、交接、失效处理全部沿用 cone_descent_ibvs**（继承）：宽门改锁、`TARGET_UNCONFIRMED`、
   末端预算（投放门计时/放宽/`DROP_GATE_TIMEOUT`/`TERMINAL_TIMEOUT`）、丢失爬升重捕获、
   `TARGET_LOST_REPEATEDLY`，语义同 [failure-handling.md](../failure-handling.md)。
2. **末端**：目标估计 = 最近 `est_window_s` 内关联检测世界坐标（感知按拍照时刻位姿反投影到
   筒顶）的中位数；发**位置指令** = 估计 − R(yaw)·瞄准偏置（瞄准偏置随高度从相机迁移到投放口，
   同 cone 的 aim 迁移），由飞控位置环对准；末端水平限速 `v_max_mps`（估计跳变时不在低空快速横移）。
3. **降高**：指令高度按 `descend_rate` 斜坡下降，速率乘锥面余量比例（水平误差 = 飞控位置到
   指令点），出锥停降；指令高度不超前实际高度 `h_lead_max_m`。
4. **投放门**：投放口世界位置到目标估计的距离 < 容差，且在投放高度带内、对地速度/水平同 cone，
   连续 `stable_hold_s`。
5. **丢失**：短丢保持估计和高度；持续丢失在估计点上方爬升（水平位置照锁，不再盲飘）；已收敛
   在投放高度丢失 = endgame，按最后估计照查投放门（有界）。

同时给 cone_descent_ibvs 一个**低增益变体**（`cone_descent_ibvs.lowgain.yaml` 叠加在 sim/real
yaml 上），匹配实测延迟，作对照。

## Consequences

- 末端精度取决于：拍照时刻位姿对齐、窗口内 EKF 漂移、飞控位置保持精度（GPS 定位下 cm 级抖动）。
  4cm 门可能偏紧，放宽路径照旧兜底。
- 飞控位置环自身也有加速度/jerk 整形，收敛小偏差 ~1–2s，但闭环在飞控内部、无外环延迟极限环。
- sim 只有在复现实机 ~0.7s 速度响应时，cone 的对照才有意义；新模块对该延迟不敏感。
- 默认算法仍是 cone_descent_ibvs，直到实飞对比完成。
