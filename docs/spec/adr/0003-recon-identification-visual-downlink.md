# 0003. 侦察区危化品标识识别改为人工肉眼图传识别，机载感知范围收窄

**Status**: Accepted

**Narrows**: [ADR-0002](0002-onboard-inference-only.md)（部分收窄，非全面推翻，见下方 Decision）

## Context

[ADR-0002](0002-onboard-inference-only.md) 基于赛规 2.2/5.8（全程禁止人工
操纵飞行器）、5.13/7.3.4（未经裁判允许打开图传电源取消资格）三条，认定
"图传回地面 + 地面处理 + 结果回传给飞行器"这条路径完全没有可行的执行
窗口，决定感知（目标识别、定位）、推理（危险化学品标识分类）、规划/
决策全部机载完成，不设计任何图传参与计算/决策的路径。

2026-07-19，队内就"图传能不能用于标识识别"这个问题直接向组委会当面
Q&A 确认，结果如下（完整摘录见
[`docs/reference/competition-rules-summary.md`](../../reference/competition-rules-summary.md)
第 5 节的澄清条目）：

- 图传设备允许在起飞前的指定窗口开机，与飞行器一起启动——7.3.4 条"未经
  裁判允许打开图传电源"的限制，指的是这个窗口之外的擅自开机，不是全程
  禁止使用。
- 侦察区危险化学品标识的识别，组委会明确要求的就是**机组人工肉眼识别**
  ——"放一个图传屏幕自己看"，不要求、也不需要机载自动分类后再把结果
  回传给飞行器。
- 这与赛规原文第 5 节"投放完毕后……机组根据飞行器传回的信息填写成绩
  记录单"一句吻合——图传本来就是设计给机组人工监看、手填成绩单用的，
  这句话此前在 ADR-0002 的分析里没有被充分注意到。

这条确认**没有**改变以下两条约束，ADR-0002 的核心结论在这两点上继续
有效：
- 2.2/5.8 条"比赛全程不允许任何人工操纵飞行器"——人工肉眼识别标识、
  手填成绩单，不构成"操纵飞行器"，两者不冲突，飞行/瞄准动作仍然必须
  全自动。
- "不存在地面处理后回传指令给飞行器"这条核心原则——图传是纯单向的
  人眼监看，不产生任何回传给飞行器的信号或指令，不形成闭环。

## Decision

- **危险化学品标识分类不进入机载感知/决策的职责范围。** 侦察区 5 个
  圆筒里哪 3 个有标识、分别是什么类别，由机组通过图传屏幕人工肉眼识别、
  手填成绩记录单完成，不由感知模块的算法判断，也不作为决策模块状态机
  的输入。
- **圆筒（目标）本身的检测与定位继续机载完成**，不受本 ADR 影响——这
  部分直接驱动飞行/瞄准动作（投放区瞄准、侦察区导航把每个圆筒带入
  摄像头视野），仍然受 2.2/5.8 条约束，不能靠地面人工介入。
- 图传设备的开机时序，按现场裁判指引在指定窗口内开启，不违反 7.3.4 条；
  具体流程属于地面操作规程，不在本仓库软件设计范围内。
- ADR-0002 的其余结论（不设计地面自动计算/决策回传路径、机载算力是
  硬约束、感知模块的目标识别与定位仍是机载工作）继续有效，本 ADR 只是
  在"标识分类"这一项具体任务上做收窄澄清。

## Consequences

- 感知模块范围明显收窄：不需要开发/训练危险化学品标识分类器，不需要
  维护跨帧目标关联（track_id）；`感知 → 决策` 的消息契约不需要携带
  分类结果字段，见
  [`05-perception-decision-interface.md`](../05-perception-decision-interface.md)。
- 图传链路（如果机体上装）成为一个新的、独立于机载软件闭环之外的
  子系统，需要满足"机组能看清标识"这个最低要求（分辨率、帧率、延迟），
  但不属于本仓库（伴随计算机软件）的设计范围，也不需要为它设计失联
  容错或低延迟保障逻辑——这点与 ADR-0002 原有结论一致。

  修订稿；如果后续拿到组委会的书面澄清或规则勘误，应以书面版本为准，
  并同步更新
  [`competition-rules-summary.md`](../../reference/competition-rules-summary.md)
  的来源说明。
