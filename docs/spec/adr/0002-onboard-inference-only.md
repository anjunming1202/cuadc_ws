# 0002. 感知/推理只在机载完成，不设计地面站计算路径

**Status**: Accepted

## Context

早期架构草案（`CUADC项目框架（初步方案）.md`）讨论过两条路线：
"机载计算"（相机图像在伴随计算机上直接做识别/决策）vs "地面站自动计算"
（图像通过图传回地面，地面电脑识别决策，再把结果传回飞控），当时没有
下结论。

《2026中国大学生飞行器设计创新大赛竞赛规则》里本项目实际报名的
**多旋翼无人机侦察与救援**章节（文档内页 36–41）原文如下（这个决策
的推理曾经用错过章节，走过一段弯路，过程记录见
[`docs/lessons.md`](../../lessons.md) 2026-07-09 条目，不在此重复）：

- **2.2 条**、**5.8 条**：飞行器启动后应以全自动方式完成比赛，比赛计时
  开始后除紧急停止外**不允许任何形式的人工操纵**——不存在"先人工起飞
  再切自主"这种过渡阶段。
- **5.13 条**：比赛期间（检录开始至本轮结束）组委会统一管理所有机组的
  飞行器、地面站、图传等设备；机组进入准备区后、"进场准备开始"口令发出
  之前，经裁判允许可以开启**除图传以外**设备的电源——图传设备被明确
  排除在准备阶段允许开机的清单外。
- **7.3.4 条**：未经裁判允许打开图传电源，直接**取消比赛资格**。

三条叠加：图传设备连开机都受严格管制，且比赛全程不允许任何人工操纵，
"图传回地面 + 地面处理 + 结果回传"这条路线没有可行的执行窗口——地面站
即使收到画面，也没有环节允许基于它做出任何操作。

## Decision

感知（目标识别、定位）、推理（危险化学品标识分类）、规划/决策全部在
伴随计算机**机载**完成，不设计、不依赖任何"图传回地面处理再回传指令"
的路径。地面站/图传设备（如果使用）只用于赛前调试和裁判监控，不参与
比赛计时开始后的任何计算或决策环节。

## Consequences

- 机载计算力（算力、功耗、实时性）成为硬约束，感知/规划模块的模型选型
  和推理耗时预算需要按机载硬件能力设计，不能假设可以把重计算卸载到
  地面站。
- `docs/spec/working-notes.md` 里原本"重新打开"的"机载计算 vs 地面站
  自动计算"开放问题正式关闭，引用本 ADR。
- 图传链路（如果机体上装了）在系统设计里降级为纯调试/监控用途，不是
  任务闭环的一部分，不需要为它设计低延迟保障或失联容错逻辑。
