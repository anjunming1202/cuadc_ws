# 00. 架构总览

> 本文档是活文档，会随实现推进持续修订——除了链接到的 ADR 记录的决策
> 外，其它内容（模块划分、数据流、状态机等）都可能在实际开发中发现
> 理解有误或需要调整而修改，这是正常迭代，不代表之前的版本"错了"。

## 范围

本仓库覆盖伴随计算机（Companion Computer）软件：感知/视觉、规划/决策、
与 ArduPilot 飞控的通信接口。飞控本身的调参、机体结构、电源、投放机构
由其它子队负责，本仓库只把它们当作外部契约引用（见
[`docs/reference/ardupilot-interface-overview.md`](../reference/ardupilot-interface-overview.md)）。

## 模块划分

- **感知/视觉**——相机图像 → 目标（圆筒）检测与定位，无状态、逐帧
  发布，不做识别结果的时序滤波/跟踪（这部分归决策模块）。危险化学品
  标识的具体类别不在机载职责范围，由机组通过图传人工肉眼识别（见
  [ADR-0003](adr/0003-recon-identification-visual-downlink.md)）。
- **规划/决策**——任务状态机、任务流程管理、航点/路径生成、识别结果的
  时序融合与去重、目标选择与确认、投放/动作决策。
- **接口层**——与 ArduPilot 的 MAVLink 通信，独立于规划/决策模块（见
  [ADR-0001](adr/0001-interface-layer-separate-module.md)）。对外
  话题/服务契约见 [`04-interfaces.md`](04-interfaces.md)。
- **日志**（横向能力，机制未定，见下方"横向关注点"）。

感知/视觉、规划/决策各自的详细设计文档还没有，两者之间的契约边界
（消息格式、职责划分、通信模式）见
[`05-perception-decision-interface.md`](05-perception-decision-interface.md)；
等各自内部设计内容长到需要拆分时再拆成独立文件（拆分规则见
[`docs/spec/README.md`](README.md)）。

**仿真 vs 真机不是两套代码**：感知/视觉、规划/决策、接口层这些模块面对
的是 MAVLink 协议，这个协议不区分对面是 ArduPilot SITL 还是真的 Pixhawk
（这正是 SITL 存在的意义）。这些模块的代码只写一份，仿真时连接
SITL、真机部署时连接真飞控，只是连接目标（连接串/串口）这一个参数不同。
`src/cuadc_sim` 只放仿真专属的资产（比赛场地世界文件、圆筒/标识模型、
拉起 SITL 的 launch 文件），不应该包含上述模块的正式实现——这是
[ADR-0001](adr/0001-interface-layer-separate-module.md)（接口层独立
成模块）的自然推论，不算独立决策，不单开 ADR。

## 顶层数据流

```
相机
  ↓
感知/视觉模块
  ↓
目标类型 / 目标位置 / 识别置信度
  ↓
规划/决策模块
  ↓
航点 / 目标高度 / 目标速度 / 目标航向 / 模式切换 / 动作指令
  ↓
接口层（MAVLink）
  ↓
ArduPilot（GUIDED 模式为主）
  ↓
遥测（位置、姿态、速度、模式、电池、GPS、Failsafe 状态……）
  ↓
接口层 → 规划/决策模块（闭环）
```

## 任务状态机（粗粒度）

```
起飞 → 飞抵投放区 → 投放标准载荷（2次）→ 飞抵灾情侦察区 → 侦察覆盖圆筒 → 返航着陆
```

细节（每个阶段内部的子状态、切换条件、任务触发开关、异常处理，含侦察区
标识识别改为机组人工图传识别的说明）见 [`06-planning.md`](06-planning.md)。

## 非目标

不覆盖：飞控内部调参（PID、Failsafe 配置等）、机体结构设计、电源/供电
系统、投放/执行机构的机械设计。这些由其它子队负责，本仓库只消费它们
对外暴露的接口（飞控侧见
[`ardupilot-interface-overview.md`](../reference/ardupilot-interface-overview.md)）。

## 横向关注点

**安全与异常处理**：不作为单独一个模块，而是分布式的：
- 飞控内部负责飞行安全相关的 Failsafe（低电、遥控失联、GPS 异常、
  地理围栏、返航/降落策略）。
- 规划/决策模块负责任务逻辑相关的异常（目标丢失、识别置信度不足、
  状态机超时、取消投放、重新搜索或请求返航）。
- 接口层/通信负责检测链路状态（telemetry 失联、连接异常）。
- 硬件层负责人工安全输入（Arming、Kill switch、Safety switch）。

具体约定待后续展开。

**日志**：飞控日志、感知结果、规划状态机阶段、通信状态、任务事件都
应该可记录，用于调试和赛后复盘。具体机制（rosbag、自定义格式，还是
两者结合）尚未讨论，留待后续决定。
