# 05. 感知 ↔ 决策 契约与职责划分

## 范围与定位

本文档定义感知/视觉模块与规划/决策模块之间的边界和通信契约，风格上
对应 [`04-interfaces.md`](04-interfaces.md)（决策 ↔ 接口层 契约）——
两份文档合起来覆盖数据流的完整链路，感知/决策各自的内部详细设计（CV
算法细节等）不在本文档范围，等内容长到需要独立维护时再拆分（拆分规则
见 [`README.md`](README.md)）。决策模块内部的任务状态机已经拆出去了，
见 [`06-planning.md`](06-planning.md)。

核心原则：**感知无状态，只负责"看到了什么"；决策负责所有任务语义
判断（这个结果够不够稳、要不要采信、该做什么）**。感知不知道当前处于
任务状态机的哪个阶段，就像接口层不知道"投放区"在哪一样——这是刻意
维持的边界，避免任务语义扩散到多个模块里。

## 技术路线

- **CV 方法**：优先用传统 CV（颜色阈值 + 形态学去噪 + 轮廓提取 + 最小
  外接圆/椭圆拟合，估计目标像素位置和视在尺寸），不引入神经网络/训练
  数据。理由：目标是已知形状的白色圆筒，场地相对可控，传统方法在机载
  算力上跑得快、可解释、不需要标注数据；侦察区标识分类已经不需要机载
  做（见 [ADR-0003](adr/0003-recon-identification-visual-downlink.md)），
  进一步降低了对训练模型的需求。如果传统 CV 鲁棒性在实测中不够（光照/
  背景干扰），后续换成轻量检测网络是备选方案，不影响下面的消息契约
  （契约只关心输出的位置/像素方位/尺寸/置信度，不关心内部用什么算法算出来的）。
- **通信模式：只用 topic，不用 service/action。** 感知按固定频率持续
  发布检测结果，决策订阅、自己决定什么时候看、看多少帧。不做成"决策
  发一次请求、感知攒好答案再返回"的模式，原因：
  1. 检测结果本质是连续流（相机一直在出帧），不是一次性算完就有唯一
     答案的离散动作，跟 service 的语义天然不匹配。
  2. 如果包成 service，"攒几帧才算数、什么时候够稳"这类任务语义判断
     会被迫塞进感知的 handler 里去实现这次调用，跟"感知无状态、时序
     判断归决策"这条边界矛盾。
  3. rclpy 默认单线程 executor 下，一个节点的所有 ROS 回调共享一根
     线程；感知节点自身的常开循环、决策节点自身的状态机 tick 与遥测/
     检测订阅，都不应该被一次阻塞式调用卡住。
- **控制流：感知默认常开（方案 A）**，节点启动后按固定频率处理相机帧、
  持续发布检测结果，不接受外部开关。传统 CV 算力开销小，MVP 阶段没有
  必要为省算力加生命周期管理。如果后续实测算力/功耗紧张，可以加一个
  决策 → 感知的开关（方案 B，语义类似接口层的 `Arm`：离散的一次性状态
  切换，用 service 合理），只影响感知要不要处理帧，不改变感知发布的
  数据契约、也不需要感知知道"为什么开/为什么关"。这个开关目前不在
  MVP 范围内。

## 职责边界：谁管什么

| 关注点 | 归属 |
|---|---|
| 目标（圆筒）检测、像素/相机系 → 世界坐标转换、位置与视在尺寸估计 | 感知 |
| 危险化学品标识识别与分类 | **不在机载软件职责范围**，机组通过图传人工肉眼识别，见 [ADR-0003](adr/0003-recon-identification-visual-downlink.md) |
| 时序融合（攒几帧、判断检测结果是否收敛/够稳）| 决策（活在具体状态内部的局部逻辑，不是独立组件） |
| 目标去重（这个圆筒是不是已经扫过了）| 决策（按位置距离阈值去重，不需要感知维护跨帧 track_id）|
| 目标选型（比如投放区挑最小的）| 决策 |
| 任务阶段/状态机 | 决策，感知对任务阶段无感 |
| 感知处理开关（如果后续加方案 B）| 决策发起、感知被动响应；纯资源控制信号，不代表感知知道任务语义 |

## 契约总览：检测结果（感知 → 决策）

> 话题名、消息类型均为暂定草案，实际实现时可能微调，不算独立决策
> （同 [`04-interfaces.md`](04-interfaces.md) 的处理方式）。

| 能力 | ROS2 通信方式 | 名称（暂定） | 类型（暂定） | 说明 |
|---|---|---|---|---|
| 目标检测结果 | topic | `/perception/detections` | 自定义 `DetectionArray.msg` | 感知按固定频率持续发布，逐帧独立、无状态，不做时序累积或跨帧关联 |

`Detection.msg`（暂定字段）：

```
string target_type       # 目前只有 "cylinder" 一种，字段先留着占位
geometry_msgs/Point position  # 世界坐标；与接口层 telemetry/local_position
                               # 同一坐标系（起飞坐标系，前/右/下，见 coordinate-frames.md），由
                               # 感知内部完成坐标转换后再发布（粗接近/PBVS 用）
float64 bearing_x        # 归一化像平面坐标 (u-cx)/fx（无量纲），末端 IBVS 用
float64 bearing_y        # 归一化像平面坐标 (v-cy)/fy（无量纲），末端 IBVS 用
float64 apparent_size     # 视在尺寸（比如外接圆半径），供"挑最小的"
                           # 这类判断用
float64 confidence
```

`DetectionArray.msg`：`std_msgs/Header header` + `geometry_msgs/Pose vehicle_pose`
+ `Detection[] detections`。**`header.stamp` = 这帧图像的拍照时刻**（不是感知处理完成
时刻）；`vehicle_pose` = 拍照时刻的机体位姿（起飞坐标系位置 + 机体→起飞坐标系四元数，感知按拍照
时刻从位姿缓冲插值）。测量与其时刻绑定发布：决策 IBVS 的姿态补偿/高度换算必须用
`vehicle_pose`（与 `bearing` 同刻），不能用决策 tick 时的最新遥测——链路有延迟时两个
时刻不同，用错时刻补偿本身就是错的（见 ADR-0010 B）。投放门等"当下状态"判断仍用实时
遥测：测量随测量走、状态随状态走。

`bearing_x/y` 是为投放**末端图像伺服（IBVS）**加的：末端对准直接用像素误差
驱动速度、对世界坐标定位误差免疫，决策依据见
[ADR-0005](adr/0005-terminal-align-visual-servoing.md)。**发的是归一化像平面
坐标（相机内参已除掉），不是原始像素**——这样决策做 IBVS 只用它自己已有的
遥测（高度 + 姿态）就能把方位换算成米级误差，仍然不需要知道相机内参/云台角，
维持下面「坐标转换在感知内部、决策拿干净数据」的边界。同一条检测里
`position`（世界坐标）给粗接近（PBVS）、`bearing_x/y` 给末端（IBVS），感知
照旧无状态、逐帧发布，两个字段都来自同一次检测，不额外增加职责。

**不需要** `hazmat_class` / `track_id` 字段——标识分类不做机载判断（见
ADR-0003），跨帧关联/去重逻辑是决策层内部状态（比如某个状态里维护的
一个"已记录位置"列表），不需要感知输出持久 ID。

## 坐标转换：谁做

像素/相机系 → 世界坐标的转换**在感知内部完成**。感知订阅接口层的
`telemetry/local_position` / `telemetry/attitude`（见
[`04-interfaces.md`](04-interfaces.md)），结合相机内参和云台角度做
反投影，直接对外发布世界坐标。决策层拿到的是干净的位置数据，不需要
知道相机参数、云台角度这些感知实现细节——这样感知内部换算法（传统 CV
换成检测网络）完全不影响决策层代码。`bearing_x/y` 同理：感知把内参除掉后
发归一化方位，决策做末端 IBVS 只用高度 + 姿态换算成米级误差，一样不碰相机
内参——所以「决策不需要知道相机参数」这条边界在加了像素观测之后依然成立。

## 与测试桩（stub）的关系

决策层单独开发/测试时，用一个桩节点代替真实感知——桩节点从
[`field-layout.md`](field-layout.md) / `cuadc_sim` 的场地生成器里读
已知的圆筒位置，按上面同样的 `DetectionArray` 契约发布（可选加噪声/
延迟/丢检模拟提前测试决策层的鲁棒性）。决策层代码不需要区分对面是桩
还是真实感知，真感知做好后换一下话题来源即可（这是
[ADR-0001](adr/0001-interface-layer-separate-module.md)"用桩替代真实
模块做测试"思路在感知/决策边界上的延伸应用）。

## 包名

暂定 `cuadc_perception`（ament_python，感知节点实现）、`cuadc_decision`
（ament_python，决策状态机节点）、`cuadc_perception_msgs`（ament_cmake/
rosidl，消息定义）——消息单独拆包的原因同 `cuadc_interface_msgs`：
rosidl 需要 ament_cmake，节点用 ament_python。均为暂定，未最终确定，
处理方式同 `cuadc_sim`/`cuadc_interface` 包名的先例。

## 侦察区标识识别的范围说明

危险化学品标识的具体类别不属于本契约、不属于感知/决策模块的机载
职责——由机组通过图传屏幕人工肉眼识别、手填成绩记录单完成，决策依据
见 [ADR-0003](adr/0003-recon-identification-visual-downlink.md)。感知/
决策模块在侦察区唯一需要做的，是把无人机导航到能让摄像头看清每个圆筒
的位置（复用投放区同一套圆筒检测算法），不涉及标识内容本身的识别或
记录。
